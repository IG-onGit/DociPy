General

DociPy is a Python command-line application that generates static HTML documentation from Markdown files.

Point it at a folder of .md files, run docipy render, and it writes a documentation site you can open in a browser or publish on your own domain.

Why use it

  • Folders become menu entries, so the structure of your files is your navigation.
  • The result is static HTML: no server, database or build pipeline to maintain.
  • Previous versions are reserved in a version folder when you raise the version number.
  • Search, copyable code blocks and syntax highlighting are built in.
  • Logo, colors, author card and main buttons are configurable.

How it works

Each docipy render runs the same pipeline in the folder where you start it:

  1. Load the configuration from assets/docipy.json. On the first run DociPy asks for the values and saves them.
  2. Scan the folder for Markdown files and sub-folders, and write the menu to menu.yaml (an existing menu.yaml is reused).
  3. Convert every Markdown file to HTML (fenced code blocks are supported) and place it in its own section.
  4. Fill the page template with your configuration, write index.html, copy missing assets and open the page in your browser.
my-docs/**/*.md ────────┐
assets/docipy.json ──────┼──► docipy render ──► index.html
menu.yaml (your edits) ──┘                      assets/  robots.txt

Installation

DociPy is distributed as a Python package. To use it:

  1. Install the module.
  2. Open any directory that contains Markdown files such as folder/files.md.
  3. Open the CLI in that directory and render.
  4. Update the documentation logo at assets/logo.ico and the author image at assets/author.png.
  5. Run docipy version to raise the version number, or docipy version 1.2.0 to set it manually.
pip install docipy
cd my-docs
docipy render

Do not change the file names in the assets folder. You can update the files themselves.

Commands

All commands run in the folder that holds your Markdown files.

CommandWhat it does
docipy renderRenders the documentation: loads or asks for the configuration, builds the menu, converts Markdown, writes index.html and opens it in your default browser.
docipy render -rRenders after deleting menu.yaml, so the menu is rebuilt from the directory tree.
docipy versionRaises the version number, reserves the previous page in the version folder and renders again.
docipy version 1.0.3Sets the version manually. It must be a valid semantic version and different from the current one.
docipy reformAsks for every configuration parameter again, keeps values you skip, then renders.

docipy version and docipy reform need an existing project (an assets/docipy.json file). Otherwise DociPy answers: Project not detected!

Menu

The menu is mapped from your directory tree and saved in menu.yaml. Edit the file, then run docipy render again to apply your changes.

  • Markdown files and folders become entries. Folders with entries inside become expandable groups.
  • Skipped on purpose: README.md, assets, version, .git, .github and .system.
  • File and folder names with special characters (anything except letters, digits, underscores, spaces and dots) are skipped with an error message.
  • Each page gets a link built from its name, for example #getting_started or #guides-install. Names written in Georgian or Russian are transliterated for these links.
  • Change an icon marker such as *circle to any Bootstrap icon *name that fits the topic.
# rebuild menu.yaml from scratch
docipy render -r

Output

By default the output sits in the folder where you ran DociPy: two folders and three files.

ItemDescription
assets/Everything the page needs: styles, scripts, highlight.js, the Bootstrap icons font, logo.ico, author.png, sitemap.xml and docipy.json.
version/Previous versions of the documentation (filled by docipy version).
index.htmlThe generated static page.
menu.yamlThe generated menu, which you can adjust.
robots.txtControls search engines. It disallows /assets/ and /version/ and points to the sitemap in assets/.

What the page includes

  • A collapsible side menu and a search box in the header.
  • A version switcher listing reserved versions.
  • A copy button on every code block, with highlight.js syntax coloring.
  • A mobile menu for small screens.
  • Meta tags, Open Graph and Twitter cards, a canonical URL, theme color and JSON-LD for search engines.

Project structure

The repository is small. The application lives in the .system folder and is built on the clight framework (it imports clight and declares the docipy command in clight.json).

DociPy/
├─ .github/workflows/publish.yml   publishes the package to PyPI
├─ .system/
│  ├─ index.py       render, version and reform commands
│  ├─ imports.py     shared imports
│  ├─ modules/
│  └─ sources/       template.html, docipy.js, docipy.scss,
│                    highlight.js, Bootstrap icons, logo.ico,
│                    author.png, sitemap.xml, robots.txt, lng/
├─ LICENSE
└─ README.md

System requirements

Running DociPy

RequirementDetails
Operating systemOS independent.
PythonPython 3 with pip. The repository does not state a minimum Python version.
Python packagesclight and markdown (listed on PyPI). The source also imports yaml (PyYAML).
BrowserAny modern browser to view the result. DociPy opens it for you after rendering.

Server or hosting

  • None required. The output is static HTML and assets.

Building from source

  • The repository has no setup.py or pyproject.toml; the .system folder is the application.
  • Releases are published to PyPI by .github/workflows/publish.yml, which installs clight and runs clight deploy on a Windows runner using the PYPI_USERNAME and PYPI_API_TOKEN secrets.
  • Include [!deploy] in a commit message to skip that publish job.
